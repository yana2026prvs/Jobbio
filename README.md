# План виходу на ринок праці — трекер (UI/UX job search plan)

Односторінковий веб-застосунок (без білд-кроку, без залежностей) — трекер 13-тижневого плану пошуку роботи для UI/UX дизайнерки. Стилізований під мобільний застосунок (телефон-рамка), все — HTML/CSS/JS в одному файлі `index.html`.

## Що всередині

- **План (Plan)** — 13 тижнів, розбиті на фази (`Кейси`, `Сайт і CV`, `Пошук`), задачі з чекбоксами-статусами та розгортайкою "Деталі". У "Деталях" можна виставити дедлайн задачі — на картці з'являється позначка 📅/🔥 (горить, якщо ≤2 дні або прострочено; гасне після позначки "Готово"). Це фіксований план — не редагується і не замінюється.
- **Відгуки на вакансії (Apps)** — воронка зверху (Надіслано → Відповіли → Співбесіда → Офер) з конверсією між етапами; пошук за назвою компанії й фільтр карток за етапом воронки; картки по кожній вакансії (компанія, посилання, опис, етап воронки, дедлайн наступного кроку з тією самою позначкою 🔥).
- **Навички (Skills)** — за замовчуванням чекліст навичок, побудований на основі реального частотного аналізу 7 вакансій (UI/UX middle, mobile + SaaS), з позначенням найслабших місць. Кнопка-шар поруч із дзвіночком відкриває **"Плани навчання"** — перемикач, що дозволяє замінити цей чекліст на власний план розвитку/абгрейду скілів: `.docx` (файл розбирається за стилями заголовків Word — `Heading1` стає фазою, `Heading2` — тижнем, рядки на кшталт "Ціль:"/"Артефакт:" розпізнаються окремо), `.txt`/`.md` або просто вставлений текст (заголовки на кшталт "Місяць 1 — ..." / "Тиждень 2 — ..." чи Markdown `#`/`##`/`###` розпізнаються евристично). Кожен завантажений план навчання рендериться тим самим board'ом фаза → тиждень → задача, що й сторінка "План", з власним прогресом і дедлайнами, які не перетинаються між планами; базовий чекліст завжди залишається доступним і незмінним. Розбір `.docx` довантажує невеличку бібліотеку (JSZip) з CDN і тому потребує інтернету одноразово; `.txt`/`.md`/вставлений текст працюють повністю офлайн.
- **Профіль (Profile)** — особистий кабінет: ім'я, пошта, професія і короткий опис досвіду. Поля зберігаються автоматично при введенні.

Дані зберігаються в `localStorage` браузера (`job-plan-statuses-v1`, `job-plan-deadlines-v1`, `job-applications-v1`, `job-skills-v1`, `job-skills-analysis-updated-v1` (дата останнього "Оновити аналіз" на Навичках), `job-profile-v1`, а також `job-learning-plans-v1`, `job-active-learning-plan-v1`, `job-learning-plan-statuses-v1` і `job-learning-plan-deadlines-v1` для завантажених планів навчання) — окремого бекенду немає.

## Встановити як застосунок (PWA)

Застосунок — це PWA: має `manifest.json`, іконки (`icons/`) і service worker (`sw.js`), тож його можна "встановити" на телефон без App Store.

**На iPhone:** відкрити сторінку застосунку в Safari → кнопка "Поділитися" → **На екран "Домівка"**. З'явиться іконка, застосунок відкриватиметься на весь екран, без адресного рядка Safari, дані з `localStorage` зберігаються.

Щоб це спрацювало на реальному iPhone (не в симуляторі), сторінка має бути доступна за URL з телефону — або задеплоєна (напр. GitHub Pages, вже є `origin` на GitHub), або в тій самій Wi-Fi мережі через IP комп'ютера (`http://<IP>:8000`; офлайн-кешування через service worker у такому разі не працюватиме, бо потрібен HTTPS — саме "На екран Домівка" це не блокує).

## Як запустити локально

Файл самодостатній, бекенд не потрібен. Найпростіше:

```bash
# з корня проєкту
python3 -m http.server 8000
# або
npx serve .
```

і відкрити `http://localhost:8000` у браузері. Можна й просто відкрити `index.html` подвійним кліком.

## Тести

Автотести лежать у `tests/index.html` — без npm, без jsdom. Вони завантажують реальний
`index.html` у прихований iframe і перевіряють код, що дійсно виконується (логіку дедлайнів,
воронку відгуків, рендер, localStorage, міграцію старих даних).

Запустити:

```bash
python3 -m http.server 8000
```

і відкрити `http://localhost:8000/tests/` у браузері. Подвійним кліком відкривати не можна —
під `file://` iframe не має спільного origin з батьківською сторінкою, і localStorage
застосунку буде недоступний тестам.

## Структура

Розмітка, стилі й логіка розкладені по файлах за призначенням (сторінка/функціональна область), а не зібрані в одному файлі — але без білд-кроку: браузер підвантажує `css/*` й `js/*` напряму через `<link>`/`<script>` теги.

```
.
├── index.html            # тільки розмітка (усі 4 сторінки + сторінка-shell) + <link>/<script> теги
├── css/
│   ├── base.css           # :root-токени, ресет, phone-frame, спільний chrome (screen-header/bottom-nav/foot), generic add-form
│   ├── plan.css            # календар дедлайнів, hero-картка, quick-filter, phase-overview, дошка тижнів/задач (спільна зі Skills-планом навчання)
│   ├── apps.css              # воронка відгуків, картки вакансій, фільтри, бейджі джерела
│   ├── skills.css             # чекліст навичок за замовчуванням
│   ├── profile.css             # картка профілю
│   └── plan-sheet.css           # bottom sheet перемикача/завантаження планів навчання
├── js/
│   ├── utils.js            # escapeHtml/truncateText/pluralize — завантажується першим
│   ├── header.js            # спільний screen-header chrome: sticky-скрол компактного бару, дропдауни (нагадування/"Ще") — без залежностей, тому завантажується другим, одразу після utils.js
│   ├── plan-data.js         # статичні дані 13-тижневого плану (WEEKBLOCKS/ALL_TASKS)
│   ├── plan.js                # статуси/дедлайни плану, taskEl(), дошка/огляд/календар/hero, notify-дзвіночок, панель нагадувань
│   ├── learning-plan.js         # парсинг .docx/.txt/.md, перемикач планів навчання, дошка навчального плану
│   ├── apps.js                    # трекер відгуків на вакансії
│   ├── skills.js                    # чекліст навичок за замовчуванням, "Оновити аналіз"/"Ще"-меню
│   ├── profile.js                     # форма профілю
│   ├── nav.js                          # перемикання сторінок нижньою навігацією
│   ├── app.js                           # bootstrap — послідовність ініціалізації (має завантажуватись останнім із "прикладних" скриптів)
│   └── register-sw.js                    # реєстрація service worker
├── manifest.json          # PWA-маніфест (назва, іконки, режим standalone)
├── sw.js                  # service worker (офлайн-кеш app shell; список ASSETS тримати синхронним із css/js)
├── icons/                 # іконки для головного екрана (192/512/apple-touch)
├── tests/
│   └── index.html         # автотести (запускаються в браузері, вантажать ../index.html в iframe)
└── README.md
```

Файли в `js/` не є ES-модулями (без `import`/`export`) — усі функції/змінні лишаються в глобальній області видимості й діляться між файлами так само, як раніше ділились усередині одного `(function(){...})()`. Усі фактичні виклики ініціалізації (перше завантаження даних і рендер) винесені в `js/app.js`, який завантажується останнім, після того як усі інші файли встигли оголосити свої функції. Виняток — `js/header.js`: він без залежностей і кілька файлів (`plan.js`, `skills.js`) викликають його `setupHeaderPanel()` одразу на своєму верхньому рівні (це підписка на подію, а не рендер, тож не порушує правило "рендер лише в app.js") — тому він підключений другим, одразу після `utils.js`, а не в кінці списку.

## Технічний стек

Ванільний HTML/CSS/JavaScript, без фреймворків і збірки. Тема — світла (CSS custom properties в `:root`, `css/base.css`). Дизайн-система: Jobbio-style світлий UI — м'який фон, картки на білому з тонкою тінню, лайм-блакитний градієнт для акцентів і завершених станів, amber-чіпи для критичних позначок.
